# AI 놀이터 2026 가을 밋업 DEMO DAY 발표 자료

| 항목 | 내용 |
|---|---|
| 세션 | Microsoft 365로 업무 자동화: 된 것과 돌아간 것 |
| 발표 | 박종민 (투케이텍 교육사업부) |
| 일시 | 2026-10-25 (일), 20분 |

발표는 세 파트로 구성했습니다.

1. **된 것: SOT tracker.** Teams 채팅으로 받은 자료를 Power Automate 흐름 7개와 Copilot Studio 에이전트 1개로 수집, 분류, 승인, 게시하고 M365 Copilot이 근거로 찾게 한 사례입니다.
2. **돌아간 것: log-work.** 업무 기록을 Loop에 남기려다 쓰기 API가 없어 Notion 데이터베이스로 옮긴 사례입니다. 석 달 동안 80건을 기록했습니다.
3. **이 자료를 만든 과정.** 원고는 Claude Code가 쓰고, 슬라이드는 PowerPoint Copilot이 빌트인 기능과 사용자 스킬로 만들었습니다. 이 README가 그 과정의 기록입니다.

## 저장소 구성

| 경로 | 내용 |
|---|---|
| `원고/` | 슬라이드 단위로 쓴 원고 4개(공통, 파트 1~3). 근거 문서 목록과 사내 정보는 지운 공개판 |
| `skills/` | PowerPoint Copilot에 올린 사용자 스킬 8개. 폴더마다 `SKILL.md`, 업로드용 ZIP 포함 |
| `발표자료.pdf` | 발표 덱 29쪽 |

## 만든 과정

### 1. 템플릿과 소재 확인

행사 측이 준 스피커 템플릿(16:9, 7장)을 열어 장표 구성, 발표자 노트의 작성 안내, 색과 글자 크기를 읽었습니다.

소재는 이미 있던 작업 기록에서 찾았습니다.

| 파트 | 읽은 기록 |
|---|---|
| 1 | SOT tracker 저장소의 커밋 88개, 설계 문서 17개, 결정 로그, 평가표 |
| 2 | Notion 업무일지 80건, log-work 스킬 개편 결정 기록 |
| 3 | 이 원고를 만든 대화 자체 |

Claude Code가 하위 에이전트 2개를 동시에 실행했습니다. 하나는 저장소에서 발표 소재를 뽑았고, 다른 하나는 PowerPoint Copilot의 사용자 스킬 형식을 조사했습니다. 각각 3분쯤 걸렸습니다.

### 2. 원고 작성

원고는 슬라이드 한 장마다 아래 항목을 적는 형식입니다.

```
## 슬라이드 2-2. 처음 목표는 Loop였다
- 템플릿: T02 본문형
- 제목: 처음 목표는 Loop였다
- 부제: 2026-07-10, 쓰기 경로를 확인한 결과
본문: …
시각 요소: …
발표자 노트:
> …
```

PowerPoint Copilot은 MD 파일을 읽지 못했습니다. 같은 내용을 docx로 바꿔 OneDrive에 올리고 참조하게 했습니다.

### 3. 말투 정리 스킬

초안으로 만든 슬라이드에서 AI가 쓴 티가 나는 표현이 반복됐습니다. 원고 4개를 세어 보니 119건이었습니다. 이 중 8가지를 발표자가 직접 골라 `deck-tone` 스킬의 규칙으로 정했습니다.

| 구분 | 규칙 |
|---|---|
| 표기 | 낫표, 제목의 긴 대시, 가운뎃점 나열, 슬라이드 본문의 '~다' 종결 |
| 문장 | 'A가 아니라 B' 반전, 교훈조 마무리 줄, 비유 동사(쌓였다, 막혔다 등), 노트의 짧은 단문 연속 |

이 저장소의 `원고/`는 정리하기 전 초안입니다. 슬라이드에는 `deck-tone`으로 정리한 문구가 들어갔습니다.

### 4. PowerPoint Copilot 사용자 스킬 8개

PowerPoint Copilot은 2026년 9월 웹, 10월 Windows부터 `SKILL.md` 형식의 사용자 스킬을 받습니다. 폴더 이름과 `name`이 같아야 하고, 앞머리에는 `name`과 `description`만 씁니다.

| 스킬 | 하는 일 | 켬/끔 |
|---|---|---|
| `deck-tone` | 문구와 노트의 말투 정리 | 켬 |
| `deck-decoration` | 템플릿 색 8개와 맑은 고딕으로 장식 | 켬 |
| `deck-redact` | 공개하면 안 되는 정보 찾기 | 켬 |
| `deck-timing` | 노트 글자 수로 발표 시간 계산 | 켬 |
| `deck-final-check` | 입력란, 장표 코드, 숫자 일치 점검 | 켬 |
| `deck-from-script` | 원고 문서로 장표 생성 | 끔 |
| `deck-changelog` | 숨긴 슬라이드에 작업 기록 | 끔 |
| `deck-screenshot` | 캡처에 번호, 강조, 가림 | 끔 |

보고만 하고 슬라이드를 바꾸지 않는 스킬은 켜 두었습니다. 슬라이드를 바꾸는 스킬 중 결과를 예측하기 어려운 것은 꺼 두고 `@이름`으로 부를 때만 썼습니다.

올리는 법: PowerPoint의 Copilot 창에서 `+` → Choose skills → Manage skills → Add skill을 누르고 ZIP 파일을 올립니다.

### 5. 검수

완성한 덱 29장을 이미지로 내보내 한 장씩 보고, 원고와 대조했습니다.

- 숫자(72회, 18/18, 0/24, 80건 등)는 원고와 일치했습니다.
- 말투 규칙 8가지 중 슬라이드에 남은 것은 없었습니다.
- 발표자 노트 1장이 한 단어로 깨져 있었고, 입력란 23개와 캡처 자리 8곳이 남아 있었습니다.
- 한국어 단어가 줄 중간에서 잘리는 곳이 4장에 있었습니다. 원인은 한글에 붙은 언어 태그(`en-US`)였고, 한글 텍스트의 언어를 `ko-KR`로 바꿔 해결했습니다.

27쪽 꾸미기 전후 비교는 단계마다 화면을 저장해 두지 않아 실제 과거 캡처가 없습니다. PowerPoint Copilot에 같은 대화에서 샘플 3장을 만들게 했고, 그중 하나를 골랐습니다. 왼쪽 "적용 전"은 현재 슬라이드에서 장식을 걷어 낸 재구성이고, 슬라이드에도 그렇게 적었습니다.

### 6. 캡처와 공개 범위

데모 캡처 4장은 별도 Claude Code 세션이 크롬에서 찍었습니다. 수집 카드는 열기만 하고 제출하지 않았고, 승인과 메시지 발송도 하지 않았습니다.

공개용 캡처는 주소창, 메일 주소, 발표자 외 사람 이름, 고객사명을 이미지 픽셀에 직접 칠해 가렸습니다. 슬라이드 위에 도형을 덮는 방식은 원본 이미지가 파일 안에 남기 때문에 쓰지 않았습니다. 캡처에 보이는 파일 이름(Flowmate, Contoso 등)은 평가용 가상 자료입니다.

PDF로 내보내기 전에 세 가지를 더 확인했습니다.

- PDF 본문 텍스트: 메일 주소, 사이트 주소, ID, 사내 경로, 발표자 외 실명을 패턴으로 검사
- 덱에 들어간 이미지 11개: 하나씩 열어 원본 캡처가 섞이지 않았는지 확인
- 문서 속성: 받은 템플릿의 제목과 작성자가 다른 행사, 다른 사람 이름으로 남아 있어 이 발표 기준으로 바꿈
