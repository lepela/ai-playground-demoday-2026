## 슬라이드 3-4. PowerPoint Copilot의 스킬

- 템플릿: T02 본문형
- 제목: PowerPoint Copilot의 스킬
- 부제: 빌트인 스킬에 더해, 2026년 9~10월부터 사용자 스킬을 올릴 수 있다

본문 (2단 비교):

| 빌트인 스킬 | 사용자 스킬 |
|---|---|
| Copilot이 처음부터 가진 기능. 덱 만들기, 슬라이드 추가, 다시 쓰기, 이미지 생성 등 | 내가 쓴 `SKILL.md` 파일 하나 |
| Choose skills 목록에 함께 나온다 | 같은 목록에 추가된다. 프롬프트에 `@이름`으로도 부른다 |
| 바꿀 수 없다 | 폴더 이름과 `name`이 같아야 하고, 앞머리에는 `name`·`description`만 쓴다 |

하단 (올리는 법):
Copilot 창 `+` → Choose skills → Manage skills → Add skill → 파일 업로드. 개인 OneDrive에 저장되고 나만 본다.

캡처 자리: Choose skills 메뉴 화면 (제작할 때 찍는다)

시각 요소: 비교 2단 패턴. 오른쪽에 캡처 자리.

발표자 노트:
> PowerPoint Copilot은 원래 빌트인 스킬로만 움직였습니다. 9월 말 웹, 10월 초 Windows부터 직접 쓴 스킬을 올릴 수 있게 됐습니다. 형식은 SKILL.md라는 마크다운 파일 하나입니다. 이름과 언제 쓰는지만 앞머리에 적고, 나머지는 자유롭게 씁니다. 올리면 제 OneDrive에 저장되고 저만 씁니다.

확인 필요: 빌트인 스킬의 정확한 이름은 공개 문서에 없다. 제작할 때 Choose skills 메뉴를 열어 보고 본문 왼쪽 열을 실제 이름으로 바꾼다.

## 슬라이드 3-5. 꾸미기 스킬 deck-decoration

- 템플릿: T02 본문형
- 제목: 꾸미기 스킬 deck-decoration
- 부제: 문구와 테마는 그대로 두고 장식만 더한다

본문 (2단):

| 하는 것 | 하지 않는 것 |
|---|---|
| 템플릿 색 8개와 맑은 고딕만 쓴다 | 테마·마스터·로고·하단 바를 바꾸지 않는다 |
| 본문 형태를 보고 패턴 7개 중 하나를 고른다 (큰 숫자, 단계 흐름, 비교 2단, 타임라인, 아이콘 목록, 표, 막대 차트) | 제목 아래 강조선, 그라데이션, 이모지를 넣지 않는다 |
| 원고의 「시각 요소」 지시를 먼저 따른다 | 문구를 고치지 않는다. 넘치면 알린다 |
| 끝나면 넘침·겹침·대비를 점검해 목록으로 알린다 | 애니메이션을 넣지 않는다 |

시각 요소: 비교 2단 패턴. 왼쪽 열 머리 남색, 오른쪽 열 머리 회색.

발표자 노트:
> 빌트인 기능으로 만든 초안은 구성은 맞지만 장표가 비슷비슷합니다. 그래서 꾸미기만 하는 스킬을 하나 만들었습니다. 템플릿에서 쓰는 색 여덟 개와 글꼴 하나만 쓰고, 본문 모양을 보고 일곱 가지 패턴 중 하나를 고릅니다. 문구는 건드리지 않습니다. 이 스킬도 Claude Code가 템플릿 파일의 색 값을 읽어서 썼습니다.

## PowerPoint Copilot 작업 순서 (발표에는 넣지 않음)

준비:

1. `skills/` 폴더의 ZIP 8개를 준비한다. ZIP마다 `SKILL.md` 하나만 들어 있다.
2. PowerPoint에서 템플릿 파일을 연다. 다른 이름으로 저장해 원본을 남긴다.
3. Copilot 창 `+` → Choose skills → Manage skills → Add skill에서 ZIP 8개를 올린다.
4. 아래 표대로 켜 둘 스킬과 꺼 둘 스킬을 정한다. 켜 둔 스킬은 Copilot이 상황에 맞춰 스스로 부를 수 있고, 꺼 둔 스킬은 `@이름`으로 부를 때만 쓴다.

| 스킬 | 하는 일 | 권장 | 이유 |
|---|---|---|---|
| `deck-tone` | 문구와 노트의 방언 8가지 정리 | 켬 | 문구만 바꾸고, 바꾼 내용을 표로 보고함 |
| `deck-decoration` | 템플릿 색과 글꼴로 장식 | 켬 | 문구를 바꾸지 않음 |
| `deck-redact` | 공개하면 안 되는 정보 찾기 | 켬 | 보고만 하고 바꾸지 않음 |
| `deck-timing` | 노트로 발표 시간 계산 | 켬 | 보고만 함 |
| `deck-final-check` | 입력란, 장표 코드, 숫자 일치 점검 | 켬 | 보고만 함 |
| `deck-from-script` | 원고 docx로 장표 생성 | 끔 | 켜 두면 고치는 요청에도 장표를 새로 만들 수 있음. 새 파트를 만들 때만 `@`로 부름 |
| `deck-changelog` | 숨긴 슬라이드에 작업 기록 | 끔 | 부를 때만 기록하는 스킬. 3-6 슬라이드를 채울 때 `@`로 부름 |
| `deck-screenshot` | 캡처에 번호, 강조, 가림 | 끔 | 이미지 위 도형 위치의 정확도를 확인하지 않았음. 캡처를 넣을 때 `@`로 부르고 결과를 눈으로 확인 |

생성, 말투 정리, 꾸미기:

| 순서 | 넣을 문장 (예) | 실제로 넣은 문장 |
|---|---|---|
| 1 | `00_공통.docx`를 참조하고: 「이 원고대로 표지, 발표자 소개, 목차, Q&A, 감사합니다 장표를 채워줘. 템플릿 장표를 그대로 쓰고 발표자 노트는 노트 칸에 넣어줘.」 | |
| 2 | `01_SOT_tracker.docx`를 참조하고: 「목차 뒤에 이 원고의 슬라이드 1-0부터 1-8까지 만들어줘. 1-0은 섹션 구분 장표를 복제하고, 나머지는 발표자 소개 장표의 제목·부제·하단 바만 남기고 본문을 원고대로 채워줘. '근거 자료'와 '넣지 않는 것' 절은 넣지 마.」 | |
| 3 | 2와 같은 방식으로 `02_log-work.docx` | |
| 4 | 2와 같은 방식으로 `03_PPT제작과정.docx` | |
| 5 | 「@deck-tone 전체 슬라이드의 문구와 발표자 노트를 정리하고, 고친 내용을 표로 알려줘.」 | |
| 6 | 「@deck-decoration 슬라이드 1-0부터 1-8까지 꾸며줘. 원고의 시각 요소 지시를 따라줘.」 | |
| 7 | 6과 같은 방식으로 파트 2, 파트 3 | |
| 8 | 「@deck-decoration 전체 슬라이드를 점검해서 걸린 것만 알려줘.」 | |
| 9 | 「@deck-screenshot 1-6 슬라이드 캡처 4장에 번호를 붙이고 이름, 링크, 주소창을 가려줘.」 | |
| 10 | 「@deck-redact 전체 슬라이드와 노트를 점검해줘.」 | |
| 11 | 「@deck-timing 파트별 발표 시간을 알려줘. 데모는 1분으로 계산해줘.」 | |
| 12 | 「@deck-final-check 최종 점검해줘.」 | |

작업 중간마다 「@deck-changelog 방금 한 거 기록해줘」, 직접 고친 뒤에는 「@deck-changelog 사람이 고친 것: 쪽, 내용, 이유」로 남긴다. 3-6 슬라이드는 「@deck-changelog 사람이 고친 곳 표 만들어줘」로 채운다.

1~4번을 `@deck-from-script`로 부르면 프롬프트가 「@deck-from-script 01_SOT_tracker.docx 원고로 1-0부터 1-8까지 만들어줘」로 줄어든다. 이미 슬라이드를 만들었으면 쓰지 않는다.

5번은 슬라이드가 30장 가까이 되면 한 번에 다 못 볼 수 있다. 그때는 파트별로 나눠 요청한다. 말투 규칙의 근거와 예문은 `skills/deck-tone/SKILL.md`에 있다.

PowerPoint Copilot은 MD 파일을 읽지 못했다(2026-10-22 확인). 원고 원본은 MD로 두고, Copilot에는 같은 내용으로 변환한 docx를 OneDrive에 올려 참조시킨다. 원고를 고치면 MD를 고친 뒤 docx를 다시 만든다.
