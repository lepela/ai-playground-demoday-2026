## 이 파트가 전하는 것

Teams 채팅으로 받은 자료를 모아 분류하고, 올린 사람이 승인하면 M365 Copilot이 근거로 찾을 수 있는 위치에 게시한다. 수집부터 게시까지는 M365 안에서 끝까지 됐다. 게시본에 붙인 메타데이터로 찾게 하는 것은 아직 되지 않았다.

## 슬라이드 1-1. 받은 자료는 채팅에 남는다

- 템플릿: T02 본문형
- 제목: 받은 자료는 채팅에 남는다
- 부제: 교육 자료·세미나 자료가 오가는 곳은 Teams 채팅이다

본문 (2단: 왼쪽 문제, 오른쪽 목표):

| 지금 | 만들려는 것 |
|---|---|
| 받은 파일은 채팅 첨부로 남거나 개인 폴더에 쌓인다 | 누구나 자기 Teams에서 가치 있는 자료를 바로 올린다 |
| 어디에 쓰였는지, 무엇과 겹치는지, 누가 봐도 되는지는 받은 사람만 안다 | 자료마다 유형·주제·공개 범위가 한 목록에 남는다 |
| Copilot에게 물어도 채팅 원본이 섞여 나온다 | 승인된 자료가 Copilot 답의 근거로 잡힌다 |

시각 요소: 왼쪽 열은 회색, 오른쪽 열은 남색 글자. 가운데 화살표 하나.

발표자 노트:
> 교육 회사라 강의 자료, 세미나 자료를 많이 받습니다. 대부분 Teams 채팅으로 옵니다. 받은 파일은 채팅에 남거나 각자 폴더에 쌓입니다. 이 자료가 어디에 쓰였는지, 다른 자료와 겹치는지, 누가 봐도 되는지는 받은 사람만 압니다. 목표는 두 가지였습니다. 누구나 자기 채팅에서 바로 올리게 하는 것, 그리고 승인된 자료를 Copilot이 근거로 찾게 하는 것입니다.

## 슬라이드 1-3. 흐름 7개, 서로 부르지 않는다

- 템플릿: T02 본문형
- 제목: 흐름 7개, 서로 부르지 않는다
- 부제: 흐름 사이는 대장 행의 상태 값으로 이어진다

본문 (가로 흐름도, 5단계로 묶음):

| 단계 | 하는 일 | 다음 단계로 넘기는 것 |
|---|---|---|
| ① 수집 | Teams 메시지 메뉴 → 첨부를 SOT 인박스로 복사 | manifest 파일 생성 |
| ② 분류 | 에이전트가 파일마다 유형·주제·공개 범위를 판단 | 대장 1행 (분류됨) |
| ③ 승인 | 올린 사람에게 메시지당 승인 요청 1건 | 승인 / 반려 |
| ④ 게시 | 승인·사내 공유 가능 행만 게시 위치에 복사 + 검색 메타데이터 | 게시됨 |
| ⑤ 누락 점검 | 매일 10:00 manifest와 대장 대조 | 빠진 행 알림 |

하단 상태 띠: `분류됨 → 승인 대기 → 승인 / 반려 → 게시됨 / 게시 실패`

시각 요소: 왼쪽에서 오른쪽으로 ①~④ 상자, ⑤는 아래쪽에서 ②와 대장을 가리키는 점선. 상자 사이 연결선에는 "상태 값" 라벨.

발표자 노트:
> 흐름은 7개인데 묶으면 다섯 단계입니다. 메시지 메뉴로 수집하고, 에이전트가 분류해서 대장에 한 줄씩 쓰고, 올린 사람이 승인하면 게시합니다. 매일 아침 10시에 빠진 행이 없는지 대조합니다. 흐름끼리는 서로 부르지 않습니다. 대장 행의 상태 값만 보고 다음 흐름이 움직입니다. 처음에는 자식 흐름으로 부르려 했는데 게시 오류가 풀리지 않아서 이렇게 바꿨고, 결과적으로 이쪽이 단순했습니다.

## 슬라이드 1-4. AI에게 맡기는 값과 정해 두는 값

- 템플릿: T02 본문형
- 제목: AI에게 맡기는 값과 정해 두는 값
- 부제: 에이전트는 판단만 하고, 사실 값은 흐름이 쓴다

본문 (원칙 3개, 각 원칙 아래 근거 한 줄):

1. 확정값과 추정값을 섞지 않는다
   - 파일 이름·경로·보낸 사람은 흐름이 manifest에서 읽는다. 에이전트는 판단 값과 메시지 번호만 넘긴다.
2. 사람이 고른 값이 우선이다
   - 평가 샘플 9건에서 수집 카드 값은 9건 모두 그대로 들어갔다. 에이전트가 정한 주제는 3건이 틀렸다.
3. 정해진 규칙으로 할 수 있는 일은 흐름으로 뺀다
   - 누락 대조는 매일 흐름이 한다. 에이전트가 실제로 건너뛴 파일 1건을 잡았다.

시각 요소: 원칙마다 아이콘 1개(자물쇠, 사람, 체크). 숫자 `9/9`, `3/9`, `1건`을 주황 굵게.

발표자 노트:
> 에이전트에게 맡긴 것은 판단뿐입니다. 파일 이름이나 경로 같은 사실 값을 에이전트가 옮겨 적게 하면 틀릴 수 있어서, 그 값은 흐름이 manifest에서 직접 읽습니다. 올린 사람이 카드에서 고른 값이 있으면 그 값을 씁니다. 평가 샘플에서 카드 값은 아홉 건 다 맞았고, 에이전트가 정한 주제는 세 건이 틀렸습니다. 에이전트가 파일을 건너뛰는 경우도 실제로 있었고, 매일 대조하는 흐름이 그 한 건을 잡았습니다.

## 슬라이드 1-5. 막힌 곳과 넘어간 방법

- 템플릿: T02 본문형
- 제목: 막힌 곳과 넘어간 방법
- 부제: 2026-10-14 ~ 10-19, 커밋 기록에서 뽑은 다섯 가지

본문 (표):

| 막힌 곳 | 넘어간 방법 |
|---|---|
| 자식 흐름 호출이 게시 오류로 막힘 | 흐름끼리 부르지 않고 대장 상태 값으로 잇는다 |
| 운영 계정은 다른 사람의 채팅 첨부를 읽을 수 없다 | 연결을 나눴다. 읽기는 실행한 사람, 쓰기는 운영 계정. 시험 흐름으로 먼저 확인 |
| 공유받은 동료의 메시지 메뉴에 흐름이 안 보임 | 권한 문제가 아니었다. 처음 한 번은 「워크플로 만들기」 목록에서 실행해야 메뉴에 뜬다 |
| 디자이너가 필터 조건의 따옴표를 빼고 저장. 검사기 오류 0 | 붙여넣은 뒤 다시 복사해 정의와 비교하고 게시 |
| 대장 자체가 Copilot 검색에 노출 | 대장·인박스는 검색에서 빼고, 게시본에만 검색용 메타데이터를 쓴다 |

시각 요소: 표. 왼쪽 열 앞에 주황 경고 아이콘, 오른쪽 열 앞에 남색 체크.

발표자 노트:
> 엿새 동안 막힌 곳이 많았습니다. 다섯 가지만 고르면 이렇습니다. 운영 계정으로는 남의 채팅을 읽을 수 없어서 연결을 둘로 나눴습니다. 읽기는 실행한 사람 권한, 쓰기는 운영 계정입니다. 동료 화면에 흐름이 안 보여서 세 시간을 썼는데, 권한 문제가 아니라 처음 한 번은 다른 메뉴에서 실행해야 하는 것이었습니다. 디자이너가 조건의 따옴표를 빼고 저장하는데 검사기는 오류를 내지 않습니다. 그래서 붙여넣은 뒤에는 다시 복사해서 비교합니다.

## 슬라이드 1-6. 데모: 메시지에서 Copilot 답까지

- 템플릿: T02 본문형 (화면 녹화 또는 캡처 4장)
- 제목: 데모: 메시지에서 Copilot 답까지
- 부제: 승인부터 게시까지 1분 12초 (운영 위치 첫 적재 기준)

본문 (캡처 4장을 2×2 또는 가로 4칸):

1. Teams 메시지 `…` 메뉴 → SOT 수집 → 카드에서 유형·공개 범위 선택
2. 대장에 행 생성 (분류됨)
3. 승인 요청 → 승인
4. Copilot 채팅에서 자료 내용으로 질문 → 게시본 인용

캡처할 때 가리는 것: 수집자·승인자 이름, 메시지 링크, 사이트 주소 표시줄.

시각 요소: 캡처 4장, 각 캡처 아래 번호와 한 줄 설명.

발표자 노트:
> 실제로 보여 드리겠습니다. 채팅 메시지 메뉴에서 수집을 누르고 카드에서 유형을 고릅니다. 대장에 한 줄이 생깁니다. 저에게 승인 요청이 오고, 승인하면 게시 위치에 복사됩니다. 운영 위치 첫 적재에서는 승인부터 게시까지 1분 12초가 걸렸습니다. 이제 Copilot에게 자료 내용을 물으면 게시본을 근거로 답합니다.

데모 대비: 현장 네트워크가 불안하면 미리 녹화한 영상을 튼다. 녹화본과 캡처 4장을 둘 다 준비한다.

## 슬라이드 1-7. 평가: 된 것과 아직인 것

- 템플릿: T02 본문형
- 제목: 평가: 된 것과 아직인 것
- 부제: 2026-10-20 1차 평가. 테스터 3명, 질의 12개 × 2회 = 72회

본문 (차트 + 해석):

| 질의 유형 | 예 | 결과 |
|---|---|---|
| 내용으로 찾기 | 자료 본문에 있는 내용을 묻는다 | 18 / 18 |
| 메타데이터로만 찾기 | 수집자·유형·주제 같은 대장 값으로 묻는다 | 0 / 24 |
| 둘을 섞어 찾기 | 내용과 대장 값을 함께 묻는다 | 2 / 18 |
| 게시 안 한 자료 묻기 | 제한·미게시 자료를 묻는다. 나오지 않으면 성공 | 10 / 12 |

하단 2줄:
- 제한 자료는 6회 모두 답에 나오지 않았다.
- 게시본에 쓴 메타데이터는 검색 조건으로 쓰이지 않았다. 원인 가설 5개(관리 속성 매핑, 질의 변환, 순위, 필드 의미, 표본)를 순서대로 가르는 중이다.

시각 요소: 가로 막대 4개(성공 비율). 18/18은 남색, 0/24는 주황. 숫자를 막대 끝에 크게.

발표자 노트:
> 평가는 테스터 세 명이 질문 12개를 두 번씩, 72번 돌렸습니다. 자료 내용으로 물으면 18번 모두 게시본을 근거로 답했습니다. 제한 자료는 한 번도 나오지 않았습니다. 그런데 수집자나 유형 같은 메타데이터만으로 물으면 24번 중 한 번도 찾지 못했습니다. 게시본에 붙인 값이 검색 조건으로 쓰이지 않는 것입니다. 원인은 아직 모릅니다. 관리 속성 매핑부터 하나씩 가르는 중입니다.

## 슬라이드 1-8. 된 것, 아직인 것

- 템플릿: T02 본문형
- 제목: 된 것, 아직인 것
- 부제: 2026-10-22 기준

본문 (2단):

| 된 것 | 아직인 것 |
|---|---|
| Teams → 분류 → 승인 → 게시가 M365 안에서 끝까지 돈다 | 메타데이터로 찾게 하기 (0/24 원인 진단) |
| 여러 사람이 각자 채팅에서 수집 (연결 분리) | 운영 환경 이전 (Copilot Studio 연결 생성 오류) |
| 46MB 파일 수집, 제한 자료 미게시 | 운영 계정을 전용 계정으로 바꾸기 |
| 빠진 행은 매일 대조로 잡는다 | 수집 대상 그룹 정하기 |

하단 한 줄: 흐름 정의와 결정 기록은 모두 저장소에 남긴다. 결정 로그는 뒤집힌 판단도 지우지 않는다.
