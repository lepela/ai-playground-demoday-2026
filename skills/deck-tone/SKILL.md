# deck-tone

슬라이드 문구와 발표자 노트에서 아래 8가지를 찾아 고친다. 이 8가지는 원고를 AI가 썼을 때 반복해서 나온 표현이다. 발표자가 2026-10-24에 직접 골랐다.

## 1. 바꾸지 않는 것

- 숫자, 날짜, 단위, 비율(`18 / 18`, `46MB`, `2026-07-10`)
- 제품명, 기능명, 메뉴 이름 (Power Automate, Copilot Studio, Choose skills 등)
- 세션 제목 "Microsoft 365로 업무 자동화: 된 것과 돌아간 것"과 섹션 이름 "된 것", "돌아간 것". 발표자가 정한 제목이다
- 문장의 뜻. 사실을 더하거나 빼지 않는다
- 슬라이드 구성, 레이아웃, 서식

뜻을 지키면서 고칠 수 없는 문장은 그대로 두고 슬라이드 번호와 문장을 알려 준다.

## 2. 표기

### 2-1. 낫표 「」를 쓰지 않는다

| 쓰임 | 바꾸는 법 | 예 |
|---|---|---|
| 화면 메뉴, 버튼 이름 | 작은따옴표 | 「워크플로 만들기」 목록 → '워크플로 만들기' 목록 |
| 말이나 글을 옮긴 것 | 큰따옴표 | 「시각 요소」 지시 → "시각 요소" 지시 |
| 강조 | 부호를 지운다 | 「된 것」을 말한다 → 된 것을 말한다 |

### 2-2. 제목에 긴 대시 —를 쓰지 않는다

- 제목에서는 콜론으로 바꾸거나, 대시 뒤를 부제로 내린다.
  - 된 것 — SOT tracker → 된 것: SOT tracker
- 본문에서는 쉼표나 괄호로 바꾼다.
  - 2. GitHub — 당시 작업 환경의 제약으로 중단 → 2. GitHub (당시 작업 환경의 제약으로 중단)

### 2-3. 가운뎃점으로 나열하지 않는다

- 낱말을 이어 적을 때는 쉼표를 쓴다.
  - 제목·부제·본문 → 제목, 부제, 본문
  - 유형·주제·공개 범위를 판단 → 유형, 주제, 공개 범위를 판단
- 그대로 두는 것: 화면이나 데이터에 그렇게 적힌 값(예: 선택지 '리서치·탐구').

### 2-4. 슬라이드 본문을 '~다'로 끝내지 않는다

슬라이드 본문(제목과 부제 제외)은 개조식으로 쓴다. 명사나 명사형(-음, -함)으로 끝낸다. 발표자 노트는 '~습니다'로 쓴다.

| 쓰지 않음 | 대신 |
|---|---|
| 대장·인박스는 검색에서 빼고, 게시본에만 검색용 메타데이터를 쓴다 | 대장, 인박스는 검색 제외. 검색용 메타데이터는 게시본에만 기록 |
| 제한 자료는 6회 모두 답에 나오지 않았다 | 제한 자료: 6회 모두 답에 나오지 않음 |
| 근거는 캘린더·메일이 아니라 그 대화에서 있었던 일이다 | 근거: 그 대화에서 실제로 한 일 |

부제는 명사구나 짧은 평서문 하나로 쓴다. 부제가 '~다'로 끝나면 명사구로 바꾼다.

## 3. 문장

### 3-1. 'A가 아니라 B'로 반전하지 않는다

부정하고 뒤집는 구조를 지우고 B만 적는다. 원인을 밝히는 문장이면 원인을 바로 적는다.

| 쓰지 않음 | 대신 |
|---|---|
| 막힌 곳은 경로였지 일이 아니었다 | Loop에는 쓰기 API가 없어 기록 위치를 Notion으로 바꿈 |
| 권한 문제가 아니었다. 처음 한 번은 다른 목록에서 실행해야 메뉴에 뜬다 | 처음 한 번은 '워크플로 만들기' 목록에서 실행해야 메뉴에 표시됨 |
| 새로 떠올린 것이 아니라 남아 있던 것을 다시 읽었다 | 기존 기록(커밋, 설계 문서, 업무일지)에서 소재 추출 |

### 3-2. 교훈조 마무리 줄을 달지 않는다

장 끝에 격언처럼 붙인 한 줄은 지운다. 그 장에 꼭 필요한 정보면 사실이나 수치 한 줄로 바꾼다.

| 쓰지 않음 | 대신 |
|---|---|
| 기록은 쌓아 두면 그 기록을 만든 도구를 고치는 근거가 된다 | (삭제) 또는 '업무일지를 근거로 스킬 속성 5개 추가' |
| 결정 로그는 뒤집힌 판단도 지우지 않는다 | (삭제) |
| 가끔 올리는 리포트에는 쓴다. 매일 쌓는 기록에는 맞지 않는다 | 리포트 게시에만 사용. 업무일지에는 미사용 |

마지막 정리 장의 요약 문장은 남기되, 위 2-4와 3-1 규칙을 적용한다.

### 3-3. 동작을 비유 동사로 적지 않는다

| 쓰지 않음 | 대신 |
|---|---|
| 80건이 쌓였다 | 80건을 기록했다 |
| 어떤 도구로 일했는지가 남았다 | 어떤 도구로 작업했는지 기록됐다 |
| 막힌 곳과 넘어간 방법 | 오류와 해결 방법 |
| Loop에서 막혔다 | Loop는 쓰기 API를 지원하지 않았다 |
| 누락 점검이 그 한 건을 잡았다 | 누락 점검이 그 한 건을 찾았다 |
| M365 안에서 끝까지 돈다 | M365 안에서 모두 처리된다 |
| 처리가 멈춰 있었다 | 처리가 실행되지 않았다 |

'돌아간 것'은 세션 제목의 표현이므로 제목과 섹션 이름에서는 그대로 둔다. 본문에서 같은 뜻을 말할 때는 '옮겼다', '바꿨다'로 쓴다.

### 3-4. 노트에서 짧은 단문을 잇달아 쓰지 않는다

발표자 노트는 소리 내어 읽는 글이다. '~습니다.'로 끝나는 짧은 문장이 세 개 넘게 이어지면 뜻이 이어지는 두 문장을 연결어미(-고, -는데, -어서, -지만)로 잇는다. 한 문장은 소리 내어 한 호흡에 읽을 수 있는 길이(대략 60자 안쪽)로 둔다.

쓰지 않음:
> 처음 버전은 Claude 세션이 처리했습니다. 잘 돌았습니다. 제가 세션을 열어야만 돌았습니다. 8월 말부터는 처리가 멈춰 있었습니다.

대신:
> 처음 버전은 Claude 세션이 처리했는데, 제가 세션을 열 때만 실행됐습니다. 그래서 8월 말부터는 처리가 되지 않았습니다.

## 4. 절차

1. 사용자가 범위를 정하지 않으면 모든 슬라이드의 제목, 부제, 본문 텍스트 상자, 표, 발표자 노트를 본다.
2. 2절과 3절의 8가지를 슬라이드마다 찾아 고친다. 한 문장에 여러 개가 걸리면 한 번에 고친다.
3. 고친 뒤 글자가 텍스트 상자를 넘치면 문장을 줄이지 말고 알린다. 서식 조정은 이 스킬이 하지 않는다.
4. 끝나면 아래 형식으로 보고한다.

| 슬라이드 | 규칙 | 고치기 전 | 고친 뒤 |
|---|---|---|---|

고치지 않고 남긴 것이 있으면 표 아래에 슬라이드 번호와 이유를 적는다.

## 5. 다른 스킬과의 순서

빌트인 기능으로 슬라이드를 만든 뒤 → `deck-tone`으로 문구 정리 → `deck-decoration`으로 꾸미기. `deck-decoration`은 문구를 바꾸지 않으므로 이 순서를 지킨다.
