# deck-redact

덱 전체를 읽고 공개하면 안 되는 정보를 찾는다. 기본 동작은 보고만 하는 것이다. 사용자가 "고쳐줘"라고 하면 4절의 표현으로 바꾼다.

## 1. 찾는 것

| 분류 | 찾는 단서 |
|---|---|
| 메일 주소 | `@`가 들어간 주소 형식 |
| 계정 이름 | 로그인 ID처럼 보이는 영문 약어, "○○ 계정", 테스터 계정 이름 |
| 테넌트, 사이트 주소 | `sharepoint.com`, `-my.sharepoint.com`, `/sites/`, `teams.microsoft.com`, OneDrive 공유 링크, 회사 도메인 |
| ID | GUID(8-4-4-4-12 형식), `19:`로 시작하는 채팅 ID, 흐름 ID, 연결 ID, 목록 ID, 세션 ID, 긴 영숫자 문자열 |
| 사람 이름 | 발표자 본인을 뺀 실명, 직함과 붙은 이름(○○ 상무, ○○ 프로) |
| 고객사, 교육 대상 회사 | 회사명, 과정명에 붙은 회사명, 회사명이 들어간 파일 이름 |
| 실제 파일 이름 | 확장자가 붙은 파일 이름 중 회사명, 사람 이름, 보고서명이 들어간 것 |
| 내부 자료 | NDA, 내부 자료, 대외비, 로드맵, 사내 전용 |
| 비용, 라이선스 | 크레딧 수, 금액, 라이선스 종류와 수량 |
| 보안 관찰 | 권한 우회, 익명 링크, 접근 경로처럼 공개하면 악용될 수 있는 관찰 |

이미지(캡처)는 읽을 수 있는 범위에서 주소창, 사람 이름, 프로필 사진, 메일 주소, 채팅 내용을 본다. 글자를 읽지 못한 이미지는 쪽 번호를 따로 적는다.

사용자가 프롬프트에 금칙어 목록을 주면 그 목록을 먼저 찾는다.

## 2. 찾지 않는 것

- 표지, 발표자 소개, Q&A, 감사합니다 장표의 발표자 이름과 소속. 발표자가 공개한 정보다
- 행사 이름, 공개 제품명, 공개 기능명
- 예시용 가상 이름(Contoso, Fabrikam 등). 다만 실제 회사로 오해받을 수 있는 한국어 가상 회사명은 "가상 이름 확인"으로 따로 적는다
- 사용자가 공개해도 된다고 말한 항목

## 3. 보고

| 쪽 | 위치 | 분류 | 찾은 문구 | 바꿀 표현 |
|---|---|---|---|---|

- 위치는 제목, 부제, 본문, 표, 노트, 이미지 중 하나로 적는다.
- 찾은 것이 없으면 "찾은 것 없음"과 함께 읽지 못한 이미지 쪽 번호를 적는다.
- 확신이 없는 항목은 분류 칸에 "확인 필요"를 붙인다.

## 4. 바꿀 표현

| 원래 | 바꿀 표현 |
|---|---|
| 회사 테넌트, 사이트 주소 | 교육 부서 사이트, 사내 M365 테넌트 |
| 운영 계정, 동료 계정 | 운영 계정, 동료 계정 A, 테스터 1~3 |
| 각종 ID | (지운다) |
| 동료, 고객 담당자 실명 | 동료 A, 고객 담당자 |
| 고객사명 | 고객사 A, 가상 고객사 |
| 실제 파일 이름 | 파일 크기와 종류로 (예: 23MB 교육 자료, 46MB zip) |
| NDA, 내부 자료 | 테넌트 밖으로 내보내기 곤란한 자료 |
| 비용, 라이선스 수치 | (지운다) |
| 보안 관찰 | (지운다) |

이미지 속 정보는 바꾸지 않는다. 가릴 위치를 알려 주고, 가리는 작업은 deck-screenshot에 맡긴다.
